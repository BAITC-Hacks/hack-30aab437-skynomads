# «Аким на 5 часов» — AI-симулятор управления городом

## Проблема

При принятии решений по развитию города необходимо учитывать одновременно несколько направлений: транспорт, озеленение, социальную инфраструктуру, безопасность и качество городских сервисов. Ограниченность ресурсов требует оценки различных сценариев и понимания того, как распределение бюджета может повлиять на качество городской среды.

## Пользователь

Городской управленец, аналитик либо пользователь симулятора.

## Задача

Разработать AI-симулятор, в котором команда получает одинаковый виртуальный бюджет и набор данных о состоянии условных районов города.

Пользователь должен принять ровно 5 управленческих решений из каталога мероприятий по следующим доступным направлениям (не более 2 решений из одного направления; минимум 3 направления в наборе):

- транспорт;
- озеленение;
- социальная инфраструктура;
- безопасность;
- городской сервис.

AI должен анализировать выбранные решения, их стоимость и предполагаемое влияние на городские показатели, после чего формировать итоговую оценку сценария и рекомендации.

## Входные данные

- фиксированный виртуальный бюджет;
- набор показателей по условным районам города;
- перечень возможных мероприятий и их условная стоимость;
- показатели по пяти направлениям городского развития.

Для хакатона может использоваться заранее подготовленный синтетический датасет, не содержащий персональных или ограниченных данных.

## Ожидаемый результат

Работающий AI-симулятор, позволяющий распределить ограниченный бюджет между городскими инициативами, принять пять решений и получить итоговый Astana Quality of Life Score с объяснением влияния принятых решений.

### Must have

- единый виртуальный бюджет для всех пользователей;
- возможность выбирать решения из 5 заданных направлений, соблюдая правила набора из `docs/data-set.json`;
- автоматический контроль превышения бюджета;
- AI-анализ принятых решений;
- расчет итогового Astana Quality of Life Score;
- объяснение сильных сторон, рисков и возможных последствий выбранного сценария.

### Опционально

- сравнение результатов нескольких команд;
- визуализация изменений показателей районов;
- AI-рекомендации по улучшению выбранного сценария;
- моделирование неожиданных городских событий, требующих перераспределения бюджета;
- автоматическая генерация краткой презентации решения команды.

## Данные/доступы

Подготовленный синтетический набор данных по условным районам города: транспортная нагрузка, обеспеченность зелеными зонами, социальной инфраструктурой, показатели безопасности и качества городских сервисов, а также перечень возможных мероприятий и их условная стоимость.

## Критерии проверки

- Все команды начинают с одинакового виртуального бюджета и исходных данных.
- Система не позволяет превысить установленный бюджет.
- Принятые решения влияют на итоговые показатели модели.
- AI формирует понятное объяснение итогового результата и основных компромиссов.
- Изменение набора решений приводит к изменению Astana Quality of Life Score.

### Проверяемый MVP-сценарий

Пользователь видит исходные показатели и каталог мероприятий, выбирает ровно пять разных мер и район для каждой районной меры, получает проверку набора и расхода общего бюджета в 100 условных единиц, затем — рассчитанный Astana Quality of Life Score и AI-объяснение сильных сторон, рисков и компромиссов. Канонические числовые данные, формулы, конфликты и пример набора приведены в `docs/data-set.json`.

| ID | Требование для MVP | Критерий проверки |
| --- | --- | --- |
| R-01 | Всем пользователям доступны одни и те же начальные данные, каталог и бюджет 100. | При новом сценарии начальные данные и бюджет одинаковы. |
| R-02 | Выбирается ровно пять разных мероприятий минимум из трёх направлений, не более двух из одного. Для районной меры нужен район, для городской район не задаётся; несовместимости запрещены. | Невалидный набор отклоняется с понятной причиной; валидный пример из датасета принимается. |
| R-03 | Суммарная стоимость не превышает 100; остаток не даёт бонуса. | Превышение отклоняется до расчёта Score; набор стоимостью 95 принимается. |
| R-04 | Показатели и итоговый Score вычисляются детерминированно по формулам, лагам, синергиям и порогам датасета. | Разные допустимые наборы могут дать разные баллы; базовый Score и пример проверяются расчётом. |
| R-05 | Реальный вызов AI получает уже рассчитанные результаты и объясняет результат, сильные стороны, риски и компромиссы без самостоятельного пересчёта чисел. | Демо показывает ответ AI для валидного набора; при сбое AI пользователь получает понятное сообщение, а не выдуманный ответ. |
| R-06 | Пустой, некорректный ввод и отсутствие необходимой конфигурации обрабатываются понятным сообщением. | Ошибочный сценарий не приводит к падению основного потока. |
| R-07 | README описывает установку, конфигурацию, запуск, демо-ввод, проверку и ограничения; секреты не включаются в репозиторий. | Участник, не писавший модуль, может повторить основной сценарий и одну ошибку по README в чистом окружении. |
