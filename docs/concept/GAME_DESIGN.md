# Game Design

## Core loop

```text
START
  ↓
EXPLORE CITY
  ↓
SELECT INITIATIVE
  ↓
SELECT DISTRICT (если scope=Район)
  ↓
ADD DECISION
  ↓
repeat until 5/5
  ↓
SIMULATE Q1..Q8
  ↓
RESULT
  ↓
AI ANALYSIS / WHAT-IF
```

## Стартовое состояние

При старте:

- Budget: `100`;
- Decisions: `0 / 5`;
- Baseline Astana QoL Score: `52.56`;
- 5 районов;
- 10 показателей;
- 14 инициатив.

Главная задача игрока — принять **ровно 5 решений** в рамках бюджета.

## Исследование города

Игрок может кликнуть район и увидеть:

- District Score;
- профиль района;
- 10 показателей;
- критические значения;
- доступные районные инициативы.

### Baseline районов

| Район | Score |
|---|---:|
| Есиль | 62.99 |
| Алматы | 57.06 |
| Сарыарка | 54.65 |
| Байконур | 56.63 |
| Нура | 49.18 |

## Выбор решений

Каждая карточка инициативы показывает:

- название;
- направление;
- стоимость;
- scope: Район / Город;
- lagQuarters;
- основные эффекты.

Если мера районная — после выбора подсвечиваются допустимые районы.

Если мера городская — она применяется ко всем районам и район выбирать нельзя.

## Ограничения

Dataset-backed rules:

- бюджет: максимум 100;
- решений: ровно 5;
- повтор одной меры запрещён;
- максимум 2 меры из одного направления;
- фактически должно быть задействовано минимум 3 направления;
- несовместимые комбинации запрещены;
- порядок решений не влияет на Score.

## Визуализация lag

Каждая мера живёт на timeline Q1–Q8.

Пример:

```text
M7 School + Kindergarten
lag = 3

Q1      Q2      Q3      Q4 ... Q8
🏗 ──── 🏗 ──── 🏗 ──── 🏫
```

Модель учитывает лаг формулой из dataset; UI только визуализирует ход времени.

## Synergy mechanic

При выборе пары с синергией UI показывает:

```text
⚡ SYNERGY DISCOVERED
M10 Safe City + M12 Digital Platform
Street Safety bonus +2
```

Dataset содержит 3 synergy pairs.

## Conflict mechanic

При конфликте:

```text
⚠ CONFLICT

Эти решения нельзя совместить.
Причина: либо BRT, либо LRT.

[Заменить] [Отмена]
```

Dataset содержит 3 incompatibility rules.

## Simulate

После 5 валидных решений активируется:

`▶ SIMULATE 2 YEARS`

Timeline идёт от Q1 до Q8.

Во время симуляции:

- стройки меняют состояние;
- объекты появляются;
- KPI обновляются;
- District Score меняется;
- цвет районов может плавно меняться.

## Result

Финальный экран показывает:

- Baseline Score;
- New Score;
- delta;
- weakest district;
- critical indicators;
- synergies;
- изменения по районам;
- AI explanation.

## Virtual citizens — POC mechanic

Условные жители используются как визуальный narrative layer.

Можно показывать 100–500 анимированных представителей, но **не заявлять**, что каждый соответствует конкретному реальному человеку.

Пример карточки:

```text
Айгерим, synthetic resident
District: Нура
Needs: school access, clinic access

После сценария:
Schools 38 → 48
Health 35 → ...
```

Текст должен опираться только на рассчитанные показатели.

## Future POC: representative agents

Допустимая следующая итерация:

- до 1M synthetic population как агрегированная модель;
- 1k–10k representative agents;
- 100–500 визуальных agents на экране.

Это **концепт развития**, не текущее требование и не реализованная возможность.
