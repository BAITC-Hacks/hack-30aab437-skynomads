# Feature Spec: городской сценарий от выбора мер до AI-объяснения

## Источники и статус

- Канонический PRD: `docs/PRD.md`, SHA-256 `8bf43c4c9a6e37ba10e4e1b14951bb0382c1f96b8125af41311e4f387cea8ee5` (проверен и одобрен для split в `current-prd.md`).
- Числовые данные и правила: `docs/data-set.json` (из `docs/data-set.odt`). При изменении данных перепроверять эталонный пример.
- Производная спецификация для реализации: `docs/specs/001-city-scenario-implementation.md`.

## Goal

За один сценарий дать пользователю выбрать городские меры в пределах бюджета, проверить их допустимость, увидеть воспроизводимый Astana Quality of Life Score и понятное AI-объяснение результата.

## User Story

Как участник симуляции, я хочу распределить бюджет между пятью инициативами для условных районов, чтобы увидеть влияние моего выбора на качество жизни и понять сильные стороны, риски и компромиссы.

## Scope

- Один общий для всех стартовый набор из пяти районов, десяти показателей и 14 мероприятий, бюджет 100 условных единиц (`R-01`).
- Выбор ровно пяти разных мероприятий и района для районных мер; проверка состава выбора, несовместимостей и бюджета (`R-02`, `R-03`).
- Расчёт новых показателей районов, районных оценок и итогового Score с учётом лагов, синергий и штрафа (`R-04`).
- Реальный AI-анализ уже вычисленного результата: сильные стороны, риски и компромиссы; пользователю виден итог (`R-05`).
- Понятная обработка пустого/неверного выбора, ошибок AI и отсутствующей конфигурации; README и демонстрационный сценарий для чистого запуска (`R-06`, `R-07`).

## Out Of Scope

Сравнение команд, история сценариев, визуализации изменений по районам как отдельная функция, неожиданные события и автогенерация презентаций. Не заявляется реальный городской прогноз: исходный набор синтетический.

## Requirements

| ID | Ожидаемое поведение |
| --- | --- |
| R-01 | Каждый новый сценарий начинается с одинаковых исходных данных и бюджета 100. Пользователь может видеть исходные показатели и каталог. |
| R-02 | Ровно пять разных мер минимум из трёх направлений, максимум две в одном; район обязателен только для районных мер. Учитываются конфликты M1/M3 в любом районе, M4/M7 и M5/M13 — в одном районе. Порядок выбора не влияет на результат. |
| R-03 | Общая стоимость не больше 100; остаток бюджета не повышает Score. Нельзя получить оценку для набора сверх бюджета. |
| R-04 | Используются строго данные и формулы `docs/data-set.json`: показатели 0–100, масштабированный лагом эффект, бонусы синергий без масштабирования, веса районных показателей и населения, 70/30 балл и штраф за каждую пару со значением строго ниже 40. Расчёт выполняется приложением, не LLM. |
| R-05 | После валидного расчёта настоящий AI-запрос получает вычисленные результаты и объясняет сильные стороны, риски и последствия; не изобретает новых чисел. Недоступность AI обозначается явно, без выдачи фиктивного анализа. |
| R-06 | Пустой или некорректный ввод, превышение бюджета, отсутствие нужной настройки и ошибка AI получают понятное сообщение без падения потока. Невалидный набор не имеет Score. |
| R-07 | README содержит технологии, установку и запуск в чистом окружении, конфигурацию без секретов, демо-набор, ожидаемые результаты, проверку невалидного ввода и ограничения. Если есть секретная конфигурация, её имена и безопасные примеры отражены в `.env.example`. |

## Edge Cases

- Меньше или больше пяти решений, повтор ID, неизвестный ID или район; городской мере передан район либо районной район не задан.
- Две несовместимые меры выбраны в разных районах (важно для M1/M3); две меры, конфликтующие только в одном районе, назначены одному или разным районам.
- Ограничения направлений нарушены, стоимость превышает 100, валидный набор стоит ровно 100; порядок решений переставлен.
- Критическое значение равно 40 (не штрафуется), меньше 40 (штрафуется); сумма эффектов больше 100 или меньше 0 обрезается до границ.
- AI-сервис недоступен либо обязательная настройка отсутствует: вычисленный результат не подменяется статичным AI-текстом.

## Acceptance Criteria

| ID | Наблюдаемая проверка |
| --- | --- |
| AC-01 (`R-01`, `R-03`) | Новый запуск показывает тот же бюджет 100 и данные; набор стоимостью 95 принимается, превышение 100 блокирует получение Score. |
| AC-02 (`R-02`, `R-06`) | Пример M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка валиден (четыре направления); повтор, отсутствие нужного района, больше двух мер одного направления и конфликты отклоняются с причиной. |
| AC-03 (`R-04`) | Без действий базовый Score соответствует 52.56 из датасета (с учётом округления); пример стоимостью 95 даёт около 56.5 и синергию M10+M12; изменение выбора меняет значения по модели. Точность и округление отображения зафиксировать до реализации. |
| AC-04 (`R-05`, `R-06`) | Успешное демо показывает реальный AI-анализ рассчитанных данных; при ошибке вызова пользователь видит явное сообщение и не получает выдуманного анализа. |
| AC-05 (`R-07`) | Новый участник по README устанавливает зависимости, задаёт конфигурацию, запускает сценарий AC-02 и повторяет один невалидный ввод. |

## Dependencies

- `docs/data-set.json` — единственный предоставленный источник чисел, каталога и правил; `docs/PRD.md` — продуктовые требования.
- Пользователь выбрал React/Express бойлерплейт (`apps/frontend/`, `apps/backend/`). Перед реализацией нужно выбрать доступную AI-интеграцию с реальным демо-доступом. API-маршруты, провайдер и переменные среды не задаются этой feature spec.
